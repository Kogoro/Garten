# Design system

Everything visual comes from the tokens at the top of `web/src/styles.css`. Change a token there and every screen follows (light, dark and "system" are three sets of the same names).

| Group     | Tokens                                                                                                                                                             | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Surfaces  | `--bg` (canvas) `--panel` (cards, sheets) `--nav` `--tint` (hover, quiet fills) `--scrim`                                                                          | Light is the base; dark and "system" redefine the same names. Neutrals are tinted towards the brand green.                                                                                                                                                                                                                                                                                                                                                                           |
| Lines     | `--line` (hairlines, 8 % black or white) `--line2` (control borders)                                                                                               | One 1 px solid border everywhere. Controls keep the stronger `--line2`                                                                                                                                                                                                                                                                                                                                                                                                               |
| Text      | `--text` `--soft` `--muted` `--ph`                                                                                                                                 | Body `--text`; helper text `--muted` (≥ 4.5:1); placeholders and timestamps `--ph` (≥ 4.5:1)                                                                                                                                                                                                                                                                                                                                                                                         |
| Accent    | `--accent` (leaf green) `--accent-hover` `--on-accent`                                                                                                             | Leaf green, **only** for the primary button, focus rings, interactive text links and the active navigation. Never for fills, badges or headings. `--pollen` (amber) marks what needs a person, `--soil` a private draft                                                                                                                                                                                                                                                              |
| Status    | `--amber*` waiting · `--red*` problem                                                                                                                              | Colour is never the only signal: every status has text or an icon. "Fine" is neutral (quiet when fine, loud when not)                                                                                                                                                                                                                                                                                                                                                                |
| Type      | `--sans` Geist · `--display` Bricolage Grotesque · `--mono` Geist Mono                                                                                             | Self-hosted from `@fontsource-variable` (no font host: offline-first, strict CSP). Display only for page and section titles. Weights 400 / 500 / 600                                                                                                                                                                                                                                                                                                                                 |
| Spacing   | `--space-1` 4 · `-2` 8 · `-3` 12 · `-4` 16 · `-6` 24 · `-8` 32 · `-12` 48 px                                                                                       | Gaps, padding and margins use these values only                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Size      | `--ctl` 40 px (buttons, fields, tappable rows), `--ctl-s` 32 px, `--h` bars; 48 px icon buttons on phones                                                          | Tap targets are at least 40 px, 44 px where the audit measures phones                                                                                                                                                                                                                                                                                                                                                                                                                |
| Shape     | `--radius-lg` 12 px (containers) · `--radius-md` 8 px (buttons, fields, rows, chips) · `--leaf-r` (the leaf)                                                       | Concentric: inner radius = outer radius − padding. The leaf (two round corners, two tight ones) is reserved for the primary action, the avatar, checkboxes and stage icons; it turns over on hover                                                                                                                                                                                                                                                                                   |
| Elevation | `--shadow-card` (two soft layers) · `--shadow-pop` (menus, dialogs, toast)                                                                                         | No hard dark shadows                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Motion    | `--ease-out` Fluent decelerate `cubic-bezier(.1, .9, .2, 1)` · `--ease-grow` · `--t-in` 250 ms · `--t-out` 130 ms · `--t-slow` 500 ms                              | Content rises in, indicators slide, the growth icon grows in place (stem, leaves, flower). Menus and toasts leave in 130 ms, dialogs leave at once. Everything collapses with reduced motion                                                                                                                                                                                                                                                                                         |
| Hierarchy | one primary action per view                                                                                                                                        | Everything else is a hairline button, a ghost button or a text link; never two solid buttons side by side                                                                                                                                                                                                                                                                                                                                                                            |
| Header    | desktop: one top bar (brand, team, four tabs, _Find anything_, your avatar with the sync dot); phones: the page bar (title, sync dot, your avatar)                 | Same on every screen. Your menu holds Agents, Connect an agent, Members & Git, Admin, Sync, Account and appearance                                                                                                                                                                                                                                                                                                                                                                   |
| Add       | **Phone:** floating button bottom right above the navigation (`Fab`). **Desktop:** a labelled _Add_ button next to the section heading (or _New_ in the list bar). | Never both: mobile patterns stay off the desktop and the other way round (the audit checks it)                                                                                                                                                                                                                                                                                                                                                                                       |
| Tabs      | Pages with several sections (Members & Git, Admin, Account, a spec) use tabs                                                                                       | Same on phone and desktop; arrow keys switch. **Two levels at most, and they look different:** level 1 is an underline strip (accent marks the active tab, it switches between views of the object), level 2 is a segmented control on the tint (neutral, it only groups content inside one tab). There is no level 3: use stacked sections, a disclosure, or one scrolling page with headings. If a group has more than four parts or long labels, use headings instead of level 2. |

Type roles: page title 24 px / 600 (18 px in the one-row phone bar) · section 16–18 px / 600 · card and row title 14 px / 600 · body 14 px (16 px on phones, iOS zooms into smaller fields) · meta 13 px · caption 12 px / 500.

Until the first sync has finished (`lastSync` is only set when it has) the Specs list shows three skeleton rows, not the cache and not "No specs yet". An interrupted first sync leaves only part of the team on the device, and the missing specs would be inserted above the visible rows (CLS 0.7). Offline, the cache is shown as it is.

Empty states recede: no frame, fill, shadow or icon, 13 px in the tertiary text colour. When nothing waits on Today the headline says so ("Nothing waits for you."), and a zero in the summary is small and grey.

A spec's stage is one growth icon (`GrowthIcon` in `web/src/growth.tsx`): seed = draft, sprout = waiting for approval, bloom = released and unchanged. Status chips (`.chip`) render as a dot plus words: grey dot = neutral, check = fine, amber = waiting, red = problem; type and id chips are plain text. Four tabs (Today, Documents, Glossary, Guardrails) on every screen; the rest lives in your menu.

Buttons in bars are compact: 32 px high in a 56 px bar on desktop, 40 px on phones. There is exactly one primary action per view: while a spec or document is open its Approve button is the primary one and the list header's New steps back to a hairline button; on Today only the top card of the stack carries the primary. The editor header reads top to bottom: actions (sync, documents, Approve, menu), title (28 px), type and status, tabs.

On phones the add button is a 48 px square with a plus (its name is the aria-label) and the editor header reads: back, Done, menu, then the title (24 px, up to three lines), type and status, the tabs. The read-first overview keeps only the Documents cell; feedback and the report are tabs.

**Navigation: four tabs.** Today · Documents · Glossary · Guardrails, as a top bar on desktop and a bottom bar on phones. **Today is where people act.** Top to bottom: the date, one sentence of what waits (the count of agent questions and feedback is `#gd-needs`), the agent line (who works, the last report; opens _Agents_), notices (paused agents, failed push, approvals or answers waiting to sync), the card stack (decisions, feedback, specs ready to bloom, proposed words and guardrails; one card at a time, _Later_ puts it at the back, _See all_ opens `/queue`), recently answered decisions, and every spec by stage (Seed, Sprout, Bloom; each heading opens the full list `/specs?stage=…`). **Documents** opens with the foundation in one slim row (Vision, Strategy and pinned documents with their first line and growth icon). **Guardrails** group rules under _Always_ and _Never_; a row shows id, folder and the sentence, no kind mark. Proposed words and rules carry the sprout. Long lists render 60 rows at a time and load more as the end comes into view (`useProgressive`). **Agents** (`/activity`) keeps the agents, the trigger, the pipeline of specs in bloom, checks, activity and team health.

A spec opens with four tabs, as in the prototype: **Content** (the editor), **Report** (what the agent built, with checks), **Feedback** (open and answered) and **History** (the draft and every released version with commit and tag, from `GET /api/teams/:id/versions?spec=…`). Rows and headings that open a page carry a right-pointing chevron. Toasts rise from the bottom left.

Components (class names): `.btn` (`.primary`, `.danger`, `.small`), `.chip` (`.ok`, `.warn`, `.bad`), `.pill`, `.card` (`.warn`, `.bad`), `.row` (list item), `.field`, `.filter`, `.sheet` (dialog with title, close button and focus trap), `.hint-card` (one-time tip), `.onb` (checklist), `kbd`. New screens use these; a new component gets a token-based style next to them.

Rules the audit enforces (`npm run ux-audit`): contrast and structure by axe-core (WCAG 2.2 AA), one `h1`, a `main` landmark, a skip link and a distinct title per page, visible focus, touch targets and input text size on phones, no horizontal overflow, long words wrap, first-screen budget on a slow phone (LCP < 2.5 s, CLS < 0.1, 300 KB), security headers.

Words: see `UI-VOCABULARY.md`.

**Platform patterns.** Phone only: floating add button, bottom tab bar, read-first editor with _Edit/Done_, approval bar, overview strip, sort/filter sheet. Desktop only: top navigation bar, labelled header buttons, sync status with words, side-by-side list and editor. Shared: tokens, chips, cards, tabs, sheets, the command palette.

## Where the app deviates from the UI Design Specification

The design follows the specification (`docs/mockup.html`, `docs/prototype.html`). Where an existing rule of the app or the accessibility audit says otherwise, the app rule wins and is listed here.

| Specification                                      | In the app                                                                     | Why                                                                                                                   |
| -------------------------------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Body 14 px                                         | 14 px on desktop, **16 px on phones**                                          | The audit requires 16 px text and inputs on phones (iOS zooms into smaller fields)                                    |
| Page title 24–28 px                                | 24 px on desktop; the phone **bar** title is 18 px, the editor bar title 18 px | The bar is one row high and the title is ellipsised; 24 px does not fit next to the approve button                    |
| Tertiary text `#8A948F` (light) / `#6B7280` (dark) | `--ph` `#66706B` / `#8A948F`                                                   | The specified values are 3.1:1 and 3.7:1; the app promises 4.5:1 for placeholders and meta text                       |
| Borders 8 % black/white                            | hairlines and cards: 8 %; **controls** (`.field`, `.search`): `--line2`        | Field boundaries need to be visible; 8 % is far below the 3:1 of WCAG 1.4.11 (`--line2` is still below it, as before) |
| Fonts loaded from a font service                   | Geist, Bricolage Grotesque and Geist Mono bundled from `@fontsource-variable`  | Self-hosted, offline-first, strict CSP: no third-party font host                                                      |
| Dropdowns and dialogs animate out in 120–150 ms    | menus and the toast: 130 ms; **dialogs close at once**                         | A delayed unmount re-opened the previous dialog's state in fast sequences (and breaks keyboard focus return)          |
| Heights from the spacing scale                     | controls are 40 / 32 / 48 px                                                   | Touch targets; all are multiples of 8                                                                                 |
| Large dividers via `<hr>` only when needed         | rows keep their hairlines in lists                                             | Lists are scanned; without lines rows run together                                                                    |
