Glossary as a folder

Every term becomes its own Markdown file under docs/glossary/; sub-folders replace the section headings of glossary.md. That gives each term a formatted definition (paragraphs, lists, code, examples), its own history and clean renames. On top: term chips with a preview in specs, a review queue for terms agents propose, and a health view that finds broken, conflicting and avoided terms. One primary action per view, quiet empty states, words from UI-VOCABULARY.md.

1 · A term, read

The definition is rendered Markdown. Structured fields sit below it: synonyms, words to avoid, terms it is easily confused with, related terms. Three tabs for the term as an object: the definition, where it is used (with the sentence), and its versions.

The time bucket in which retries of one Invoice run count as the same attempt. A new window opens when the Idempotency key changes.

A window

  • starts with the first delivery attempt,
  • closes after ATTEMPT_WINDOW_MINUTES (default 30),
  • is never reopened – a late retry starts a new window.

Example

Invoice 2026-118 · attempts 09:00, 09:12, 09:41
→ windows A, A, B (09:41 is after 09:30)

The folder model

What changes underneath. The Git repository stays readable for people and agents without the app.

One file per term

Sub-folders are the glossary folders. The file name is the term as a slug; the term itself is in the front matter, so it may contain any characters.

docs/glossary/
  billing/
    attempt-window.md
    dunning.md
    invoice-run.md
  payments/
    idempotency-key.md
    settlement.md
  general/ …
  _proposed/           ← agent drafts, never live
    grace-period.md

---
term: Attempt window
aliases: [retry window, window]
avoid: [retry period]
distinct: [Retry budget]
see: [Idempotency key, Ledger entry]
source: global:7c1e…@3     # only when imported

Behaviour

  • Going live: every file under glossary/ is a foundation document, as glossary.md is today – live after you stop typing, or by an approver if the team turned that off. _proposed/ never goes live.
  • History: the History tab is the Git log of one file.
  • Rename: move the file and rewrite #[…], [[…]] and “See also” in one commit.
  • GLOSSARY.md is still generated at the team root for agents that only read the repository; it now includes the full body.
  • Definition blocks in specs stay as they are and appear under “In specs & documents”; Health shows when they disagree with a term file.

Migration

  • On first start after the update the server splits glossary.md: each definition becomes a file, each section heading a folder, terms above the first heading go to general/.
  • Existing agent drafts glossary/from-<source>.md are split into _proposed/.
  • One commit, “Glossary: one file per term”. glossary.md is removed; old links to it open the Glossary page.

Agents (MCP)

  • get_glossary returns the Markdown body plus avoid and distinct; new optional spec parameter returns only the terms that spec uses.
  • get_team_context lists terms with their first paragraph to keep it short.
  • New propose_term; derive_from_document writes to _proposed/.

Open decisions

  • Folders: one level only (as today), or nested? The mockup assumes one level.
  • Should accepting a proposed term need the approve role, or is write enough?
  • Should “words to avoid” block Approve, or only warn? The mockup only warns.
  • Team glossary export/import as a ZIP of the folder, or CSV like the global glossary?
